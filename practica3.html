Comandos GitHub

Definir lo que hacen los siguientes comandos:

Muestra el estado actual del repositorio. Indica qué archivos han sido modificados, cuáles están en el área de preparación (staging area) listos para commit, y cuáles son archivos nuevos que aún no están siendo rastreados por Git. También muestra la rama actual en la que te encuentras trabajando.

git init

Inicializa un nuevo repositorio Git en el directorio actual. Crea una carpeta oculta llamada .git que contiene toda la estructura necesaria para que Git pueda empezar a rastrear los cambios en tus archivos. Este es el primer comando que se ejecuta cuando quieres comenzar a usar control de versiones en un proyecto nuevo.

git add .

git add ruta_del_archivo

git restore .

git restore ruta_del_archivo

git reset --soft HEAD~1

git restore --staged .

git clean -f

El comando git clean -f se utiliza para eliminar del directorio de trabajo todos los archivos que no están siendo rastreados por Git (no han sido agregados con git add ni forman parte de ningún commit); la opción -f significa force y es obligatoria para evitar borrados accidentales, ya que estos archivos se eliminan definitivamente; este comando no borra archivos que sí están en seguimiento (tracked), solo los no rastreados, y si quieres ver primero qué se eliminaría sin borrarlo puedes usar git clean -n.

git merge --abort

El comando git merge --abort se utiliza para cancelar un proceso de fusión (merge) que está en conflicto, devolviendo el repositorio exactamente al estado en el que estaba antes de intentar hacer el merge; es decir, deshace todos los cambios que Git aplicó durante la fusión fallida y elimina los conflictos pendientes, permitiéndote volver a intentar el merge más tarde o tomar otra decisión, y solo funciona si el proceso de merge aún no ha sido completado con un commit.
